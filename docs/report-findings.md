# Mobilewright Report Findings (Phase 0)

| # | Question | Answer / Finding |
|---|---|---|
| 1 | Does `@mobilewright/test` export `test.step`, options? | **Yes.** A scratch TS compilation test confirms `@mobilewright/test` exposes `test.step` with support for standard Playwright options including `box` and `location: { file, line, column }`. |
| 2 | What values does `box` accept? Does it hide children? | `box: true` is supported (compiles successfully). Standard Playwright behavior for `box: true` encapsulates inner errors to the parent step call-site. It does **not** hide child steps in the HTML report; they remain visible and collapsible inside the parent. |
| 3 | Does `@mobilewright/test` export `expect` with `toBeVisible`? Timeouts? | **Yes.** Context7 confirms `expect(locator).toBeVisible()` is available. It defaults to 5000ms. Action timeouts (`use: { actionTimeout }`) also default to 5000ms. Both can be configured globally in `mobilewright.config.ts` or per-call via `{ timeout: N }`. |
| 4 | Is there a `locator.describe()` equivalent? | **No.** Context7 docs for locator methods do not mention `locator.describe()`. We must rely on interpolating locator names in the `@step` template strings (e.g., `@step('Select country "{0}"')`). This limitation will be added to the upstream issue in Phase 6. |
| 5 | Supported reporters? Config keys for screenshots/video/trace? | **Yes.** Reporters supported: `list`, `html`, `json`, `blob`. Video is supported via `video: 'on' \| 'on failure' \| 'off'`. Screenshots are supported. Trace-viewer is **not documented** in the roadmap or docs retrieved via Context7, so we will omit trace from our config updates. |
| 6 | Does TS transform accept standard TS 5 decorators? | **Yes.** Checking `tsconfig.json` reveals `"experimentalDecorators"` is missing/false and target is `"ESNext"`, meaning modern TS 5 decorators are the standard in this repo. |
| 7 | What does `locator.tap() ✕ 7` mean? | Context7 confirms Mobilewright locator actions "auto-wait for the element to be visible, enabled, and have stable bounds". The `✕ 7` simply means the action was auto-retried 7 times during the wait phase before succeeding. It is **not a test failure**, just standard framework observability. |
| 8 | What runs inside the 14.9s Before Hooks block? | The `authFixture.ts` logs in the user (`loginPage.login(...)`). We can definitely wrap fixture code inside `test.step('Login user', ...)` to break down this time in the report. |
